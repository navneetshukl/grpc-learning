## What is New vs Stage 04

Stage 04 left you with a `.proto` file — just a text file. Nothing was generated. This stage installs the toolchain and **compiles** that text file into real Go code that your program can import.

---

## The Three Tools You Need

| Tool | What it does |
|---|---|
| `protoc` | The Protocol Buffer compiler. Reads `.proto`, knows about types, but does not know any language. |
| `protoc-gen-go` | A Go plugin for `protoc`. Generates the message structs (`greet.pb.go`). |
| `protoc-gen-go-grpc` | A Go plugin for `protoc`. Generates the gRPC client stub and server interface (`greet_grpc.pb.go`). |

Think of it as a pipeline:

```
greet.proto
    │
    ▼
protoc (orchestrator)
    ├──► protoc-gen-go ─────► greet.pb.go        (messages)
    └──► protoc-gen-go-grpc ► greet_grpc.pb.go   (gRPC client + server)
```

`protoc` reads the file, then calls each language plugin. Each plugin emits its own output file.

## Understanding `greet.pb.go` (Message Types)

This file is generated by `protoc-gen-go`. It contains Go **structs** for each message defined in your `.proto` file.

### The Two Structs

```go
// GreetRequest — the input message
type GreetRequest struct {
    state         protoimpl.MessageState  // Internal gRPC state tracking
    Name          string                 `protobuf:"bytes,1,opt,name=name,proto3" json:"name,omitempty"`
    unknownFields protoimpl.UnknownFields // Tracks unknown fields from the wire
    sizeCache     protoimpl.SizeCache    // Caches the serialized size
}

// GreetResponse — the output message
type GreetResponse struct {
    state         protoimpl.MessageState
    Result        string                 `protobuf:"bytes,1,opt,name=result,proto3" json:"result,omitempty"`
    unknownFields protoimpl.UnknownFields
    sizeCache     protoimpl.SizeCache
}
```

Notice the struct tag on `Name`:
```
protobuf:"bytes,1,opt,name=name,proto3"
```

This tells the Protobuf library:
- `bytes` = wire type (means string)
- `1` = field number (from your `.proto`: `string name = 1`)
- `opt` = optional field
- `name=name` = the wire name
- `proto3` = using proto3 syntax

### The Getter Methods

Every field gets a `Get<FieldName>` getter method automatically generated:

```go
func (x *GreetRequest) GetName() string {
    if x != nil {
        return x.Name
    }
    return ""
}
```

You call `req.GetName()` instead of `req.Name`. This is the standard Go convention in generated code.

### The Raw Descriptor (Internal)

```go
const file_greet_proto_rawDesc = "\ngreet.proto\x12\x05greet..." + ...
```

This is the `.proto` file encoded as binary bytes. It is used for reflection — when gRPC needs to marshal or unmarshal messages at runtime, it uses this. You do not need to touch or understand this.


## Understanding `greet_grpc.pb.go` (Client + Server Interfaces)

This file is generated by `protoc-gen-go-grpc`. It contains: the client interface, client implementation, server interface, unimplemented fallback, and registration function.

### The Client Interface (What your code uses)

```go
type GreetServiceClient interface {
    Greet(ctx context.Context, in *GreetRequest, opts ...grpc.CallOption) (*GreetResponse, error)
}
```

This is what you call from your client code. It matches exactly what you defined in the `.proto`.

### The Client Implementation (How the stub works)

```go
type greetServiceClient struct {
    cc grpc.ClientConnInterface  // The TCP connection
}

func NewGreetServiceClient(cc grpc.ClientConnInterface) GreetServiceClient {
    return &greetServiceClient{cc}
}

func (c *greetServiceClient) Greet(ctx context.Context, in *GreetRequest, opts ...grpc.CallOption) (*GreetResponse, error) {
    out := new(GreetResponse)
    err := c.cc.Invoke(ctx, GreetService_Greet_FullMethodName, in, out, opts...)
    if err != nil {
        return nil, err
    }
    return out, nil
}
```

**This is the key part.** The client method:
1. Marshals `GreetRequest` to binary Protobuf
2. Calls `c.cc.Invoke(...)` — sends the request over the gRPC channel
3. Waits for the response
4. Unmarshals the response back into `GreetResponse`

This is the "stub" we talked about in Stage 03. You never see any of this — you just call `client.Greet(ctx, req)`.

### The Server Interface (What your server must implement)

```go
type GreetServiceServer interface {
    Greet(context.Context, *GreetRequest) (*GreetResponse, error)
    mustEmbedUnimplementedGreetServiceServer()
}
```

**This is what YOUR server must implement.** You will write a struct that satisfies this interface.

### The Unimplemented Fallback (Forward Compatibility)

```go
type UnimplementedGreetServiceServer struct{}

func (UnimplementedGreetServiceServer) Greet(context.Context, *GreetRequest) (*GreetResponse, error) {
    return nil, status.Error(codes.Unimplemented, "method Greet not implemented")
}
```

This returns a clear error for any method you do not implement. You embed this in your server struct so that when the proto evolves (new methods are added), your server does not crash — it just returns "not implemented" for the new methods.

### Service Registration

```go
func RegisterGreetServiceServer(s grpc.ServiceRegistrar, srv GreetServiceServer) {
    s.RegisterService(&GreetService_ServiceDesc, srv)
}
```

You call this from your server's `main()` to register your server with gRPC.


## The Big Picture: Where Each Piece Lives

```
greet.proto
    │
    ├──► protoc-gen-go ──────► greet.pb.go
    │                              ├── GreetRequest struct  ← server reads this
    │                              └── GreetResponse struct ← client reads this
    │
    └──► protoc-gen-go-grpc ─► greet_grpc.pb.go
                                   ├── GreetServiceClient       ← YOUR CODE calls this (client)
                                   ├── NewGreetServiceClient() ← YOUR CODE calls this (client)
                                   ├── greetServiceClient{}    ← (internal stub)
                                   ├── GreetServiceServer     ← YOUR CODE implements this (server)
                                   ├── UnimplementedGreetServiceServer ← YOU embed this
                                   └── RegisterGreetServiceServer() ← YOU call this (server)
```

**Summary of who uses what:**
- **Client code**: calls `NewGreetServiceClient()`, uses `GreetServiceClient`
- **Server code**: implements `GreetServiceServer`, embeds `UnimplementedGreetServiceServer`, calls `RegisterGreetServiceServer()`
